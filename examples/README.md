# `examples/` stack

Full integration-test deployment of Magic Conch Shell: TLS gateway → router →
auth (generic OIDC/OAuth2 + JWT) → chat/upload services → LLM core.

```
Client (integration_test.go)
  │  HTTPS :443
  ▼
gateway (Caddy)
  │  UDS
  ▼
nautrouds  ── reads examples/nautrouds/Ntufile ──┐
  ├─ */oauth2/*        → oauth2-provider          │  all UDS,
  ├─ */auth/*          → auth-service             │  shared volume
  ├─ POST /api/upload  → auth-service(/verify) → fileupload
  ├─ */api/*           → auth-service(/verify) → magic-conch-api
  └─ */health          → nautrouds built-in $health
                                                   │
auth-service ──DATABASE_URL──▶ postgres           │
             ──REDIS_URL─────▶ redis ◀─────────────┘
core ──LLM_API_KEY──▶ Gemini API
core ──GRPC_ADDRESS(UDS)──▶ magic-conch-api
```

Every inter-service call runs over Unix domain sockets on the shared
`nautrouds_sockets` volume; only `gateway` exposes a TCP port (`443`). Public API
contract for everything nautrouds routes: [`openapi.yml`](openapi.yml). `core`'s
gRPC surface is internal-only and isn't part of that contract — see its `.proto`
at `core/structs/structs.proto` and the summary below.

Every HTTP service here (except the test `oauth2-provider`, which speaks plain
OAuth2/OIDC) wraps JSON the same way: `{"success": bool, "message": <T>}`, and
replies to any `5xx` with a fixed generic message while logging the real error
server-side.

## Setup

Create `examples/.env` with the Gemini API key and a filetoken signing key
shared by `fileupload` (signs) and `core` (verifies):

```env
LLM_API_KEY=your_gemini_api_key
FILE_TOKEN_KEY=k1:<base64url secret, at least 32 bytes>
```

Generate the secret with:

```bash
echo "k1:$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')"
```

Then start the stack and run the end-to-end test:

```bash
docker compose up -d
cd integration_test
go test ./...
```

## gateway (Caddy)

**Image:** `caddy:2.10.0` · **Config:** `examples/Caddyfile`

Only service with a published TCP port (`443:443`). Terminates TLS with the
self-signed cert in `examples/certs/` (generated by `certs/gen-certs.ps1`, SAN
covers `gateway`/`localhost`/`127.0.0.1`) and reverse-proxies everything to
nautrouds' entrypoint socket. No routing logic lives here — Caddy is a dumb
TLS→UDS pipe.

```
{$CADDY_HOST:0.0.0.0}:{$GATEWAY_PORT:443} {
    tls {$TLS_CERT_FILE:...} {$TLS_KEY_FILE:...}
    route { reverse_proxy unix//var/run/nautrouds/entrypoints/nautrouds-0.sock }
}
```

`CADDY_HOST`/`GATEWAY_PORT`/`TLS_CERT_FILE`/`TLS_KEY_FILE` come from the
environment, with current values as fallback defaults. Changing `GATEWAY_PORT`
also needs a matching update to `docker-compose.yml`'s `ports:` mapping.

## nautrouds

**Image:** `lucap9056/nautrouds:26-06.19-05` · **Config:** `examples/nautrouds/Ntufile`
**Docs/source:** https://github.com/nautrouds/nautrouds

Reverse proxy / service router — dials every backend over UDS, per the routing
table in the Ntufile shown above. Full syntax reference (wildcards, `$`-prefixed
middlewares/virtual services, the `service(/path)` inline-middleware-chaining
form) lives in the upstream repo linked above; don't duplicate it here.

Two things worth calling out because they're specific to *this* Ntufile:

- **`*/api/[|*]`** — `[|*]` is the default catch-all remainder ("empty or
  anything"), so this rule means "any method, `/api/` prefix, plus whatever's
  left" — i.e. everything under `/api/` not already claimed by the more specific
  `POST */api/upload` rule above it.
- **`auth-service(/verify)`** — chains `auth-service`'s `/verify` endpoint as a
  gate before forwarding. A `204` response's headers
  (`X-Forwarded-User-ID`/`X-Forwarded-Device-ID`) get injected into the
  downstream request; a non-2xx short-circuits straight back to the client.

Healthcheck (`test -S .../nautrouds-0.sock`) only confirms the socket file
exists, not that nautrouds can reach its backends.

## oauth2-provider

**Image:** `oauth2-test-provider:local` (built locally, not published)
**Source:** https://github.com/lucap9056/auth-middleware/tree/main/oauth2/test-provider

A deliberately insecure OIDC/OAuth2 stub for E2E testing — **never use outside a
test environment.** `/auth` grants a code and redirects immediately with **no
credential check**. Every login authenticates as the same fixed identity, set via
env vars (`USER_SUB`/`USER_EMAIL`/`USER_NAME`, defaults `test-user-001` /
`user@example.com` / `Test User` — not overridden in `docker-compose.yml`).
`/token` returns an **unsigned (`alg:none`) `id_token`**. Endpoints:
`/.well-known/openid-configuration`, `/auth`, `/token`, `/userinfo`.

Routed through the gateway (not called directly) because
`OAUTH2_AUTH_URL=https://localhost/oauth2/auth` sends the browser here as part of
the client-facing login flow, not just service-to-service.

## auth-service

**Image:** `lucap9056/oauth2-middleware:2.0.0`
**Source:** https://github.com/lucap9056/auth-middleware/tree/main/oauth2

Repo is named `auth-middleware`; its `/oauth2` module is what ships as the
`oauth2-middleware` image (same project, not two). The repo also has independent
`/jwt` and `/database` modules — `init-sql-fetcher` pulls `init.sql` from
`/database` at a pinned commit.

Generic OAuth2/OIDC login + JWT session middleware (Discord/Google/GitHub/any
OIDC/OAuth2), pointed at `oauth2-provider` here via
`OIDC_ISSUER_URL=https://gateway/oauth2`. Three operational modes gated by
`DATABASE_URL`/`PASS_OAUTH_TOKEN`; this deployment sets `DATABASE_URL` but not
`PASS_OAUTH_TOKEN`, landing in **Stateful Revoke**: mints its own JWT, then
revokes the provider's tokens.

Routes (mounted at `/auth/*`, prefix stripped before reaching the service):

| Method & path | Auth | Returns |
|---|---|---|
| `GET /login` | — | `{message:{url, verifier?}}` (`verifier` unused here — that's client-held-PKCE mode) |
| `GET /callback` | query `code`,`state`; optional header `X-Device-Name` | `{message:{access_token, refresh_token}}` |
| `GET /verify` | Bearer | `204` + `X-Forwarded-User-ID`/`X-Forwarded-Device-ID`, or `401` |
| `POST /refresh` | cookie/header/body refresh token | `{message:{access_token, refresh_token}}` (rotates both) |
| `POST /refresh-access` | same | `{message:"<access_token>"}` (access only) |
| `POST /logout` | same | `{message:"Logged out and device session revoked"}` |
| `DELETE /users/me` | Bearer | `{message:"Account deleted"}`, cascades to `user_devices` |
| `GET /health` | — | `200 OK` |

`GET /verify` is also nautrouds' chained auth middleware for `/api/*`, but since
`*/auth/*` routes here wholesale it's directly reachable too.

Entrypoint runs `update-ca-certificates` first (trusting `gatewayCA.cert`) so it
can validate the gateway's self-signed cert when calling back through
`OAUTH2_TOKEN_URL=https://gateway/oauth2/token`.

## core

**Image:** `ghcr.io/lucap9056/magic-conch-shell/core:3.0.0` · **Source:** `core/` (this repo)

The LLM engine, served over gRPC at `GRPC_ADDRESS=unix:///var/run/nautrouds/core.sock`
for `magic-conch-api`. Contract is `core/structs/structs.proto`: unary
`AssistantService.Chat(Request) → Response`, where
`Request{language: Language, current_message, history_messages}` and
`PromptMessage{parts: []PromptPart{type, content, mime_type}}`. Errors are gRPC
status codes whose message is a user-facing reply.

Key env vars: `LLM_API_KEY` (Gemini — ⚠ `examples/.env` holds a real key in
plaintext, gitignored but treat as sensitive), `MODEL_NAME`, and
`FILE_TOKEN_KEYS=${FILE_TOKEN_KEY}` to verify the filetokens issued by
`fileupload`. On startup it lists the models available to `LLM_API_KEY` and
exits if `MODEL_NAME` is missing from that list. The compose healthcheck runs
`grpc_health_probe` against the gRPC socket, and `magic-conch-api` waits for it.

## fileupload

**Image:** `ghcr.io/lucap9056/magic-conch-shell/fileupload:2.0.0` · **Source:** `fileupload/` (this repo)

`POST /upload` (mounted at `/api/upload`; nautrouds validates the JWT upstream).
Accepts `multipart/form-data` field `file`, max 20 MiB. MIME sniffed via
`http.DetectContentType`, falling back to extension-based detection; allow-list
is `image/png`, `image/jpeg`, `image/webp`, `image/heif`, `image/heic`. Uploads to
the Gemini Files API, signs `{uri, mime, exp}` into a filetoken with
`FILE_TOKEN_KEY`, and returns `{message:{key: "<filetoken>", mime_type}}`. The
token is valid for 47h, within the 48h Gemini Files retention. `REDIS_URL` caches
issued tokens per file hash so re-uploading the same image returns the same token.

`GEMINI_API_KEY` and `core`'s `LLM_API_KEY` must belong to the same Gemini
project — here both read `${LLM_API_KEY}`.

## magic-conch-api

**Image:** `ghcr.io/lucap9056/magic-conch-shell/httpserver:3.0.0` · **Source:** `httpserver/` (this repo)

Thin HTTP↔gRPC bridge to `core` — the actual chat endpoint. `GET /health`, and
`POST /` (mounted at `POST /api/`; nautrouds validates the JWT upstream). Body is
decoded with `protojson`, max 1 MiB: `language` takes `LANGUAGE_EN`/`LANGUAGE_ZH`
(or `1`/`2`), field names accept snake_case or camelCase, unknown fields → `400`,
and `current_message` is required. Calls `core` over gRPC with a 5s timeout and
maps the status code:

| gRPC code | HTTP | `message` |
|---|---|---|
| `InvalidArgument`, `FailedPrecondition` | `400` | `core`'s user-facing reply |
| `ResourceExhausted` | `429` | `core`'s user-facing reply |
| `Unavailable` | `503` | `service temporarily unavailable` |
| `DeadlineExceeded`, `Canceled` | `504` | `request timed out` |
| anything else | `500` | `internal server error` |

## postgres

**Image:** `postgres:16-alpine` — backs `auth-service` only. Schema isn't in this
repo: `init-sql-fetcher` curls `database/init.sql` from a **pinned commit**
(`1e17700df4f504fc11288a4d6ef679f2d7856f06`) of the `auth-middleware` repo.
Bumping `auth-service`'s version without updating that commit risks schema drift.

```sql
users        (user_id PK, username, email UNIQUE)
user_devices (device_id PK, device_name, user_id FK → users ON DELETE CASCADE,
              secret, updated_at [indexed])
```

Data persists to `./postgres_data` (bind mount, gitignored) — delete it to reset
the DB.

## redis

**Image:** `redis:7-alpine` — shared, unnamespaced beyond key prefixes:

| Consumer | Key pattern | Purpose | TTL |
|---|---|---|---|
| `fileupload` | `fileupload:token:<mime>:<sha256>` | file hash → issued filetoken | token lifetime minus 5 min (~47h) |
| `auth-service` | internal (PKCE state, refresh token cache) | login-flow state + session cache | state: short-lived; tokens: `REFRESH_TOKEN_TTL` (24h) |

No persistence configured — a restart drops pending logins and cached refresh
tokens, forcing re-login, but doesn't touch `postgres`-backed user/device rows.
