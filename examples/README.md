# `examples/` stack

Full integration-test deployment of Magic Conch Shell: TLS gateway →
auth (generic OIDC/OAuth2 + JWT) → chat/upload services → LLM core.

```
Client (integration_test.go)
  │  HTTPS :443
  ▼
gateway (Caddy) ── reads examples/Caddyfile
  ├─ /health           → respond "OK"
  ├─ /oauth2/*         → dex:5556
  ├─ /auth/*           → corvauth:80
  ├─ POST /api/upload  → forward_auth corvauth/verify → fileupload:8080
  └─ /api/*            → forward_auth corvauth/verify → magic-conch-api:8080
                                                        │ gRPC
                                                        ▼
                                                     core:50051 ──▶ Gemini API
corvauth ──▶ postgres, redis, dex (token/userinfo)
fileupload ──▶ redis, Gemini API
```

Services talk over TCP on the compose network; only `gateway` publishes a port
(`443`). Public API contract for everything the gateway routes:
[`openapi.yml`](openapi.yml). `core`'s gRPC surface is internal-only — see its
`.proto` at `core/structs/structs.proto` and the summary below.

Every HTTP service here (except `dex`, which speaks plain OAuth2/OIDC) wraps
JSON the same way: `{"success": bool, "message": <T>}`, and replies to any
`5xx` with a fixed generic message while logging the real error server-side.

## Setup

Create `examples/.env` with the Gemini API key and a filetoken signing key
shared by `fileupload` (signs) and `core` (verifies):

```env
LLM_API_KEY=your_gemini_api_key
FILE_TOKEN_KEY=k1:<base64url secret, at least 32 bytes>
```

Generate the secret with:

```bash
echo "k1:$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')"
```

Then start the stack and run the end-to-end test:

```bash
docker compose up -d
cd integration_test
go test ./...
```

## gateway (Caddy)

**Image:** `caddy:2.10.0` · **Config:** `examples/Caddyfile`

Only service with a published port (`443:443`). Terminates TLS with the
self-signed cert in `examples/certs/` (generated by `certs/gen-certs.ps1`, SAN
covers `gateway`/`localhost`/`127.0.0.1`) and routes requests:

| Route | Upstream | Notes |
|---|---|---|
| `/health` | — | `respond "OK" 200` |
| `/oauth2/*` | `dex:5556` | path kept (Dex's issuer path is `/oauth2`) |
| `/auth/*` | `corvauth:80` | `/auth` stripped |
| `POST /api/upload` | `fileupload:8080` | `verified_api`, `/api` stripped |
| `/api/*` | `magic-conch-api:8080` | `verified_api`, `/api` stripped |

The `verified_api` snippet runs in order inside a `route` block:

1. Removes client-supplied `X-Forwarded-User-Email`/`X-Forwarded-Device-ID`/`X-Forwarded-Username`.
2. `forward_auth corvauth:80` calls `/verify` with the request's `Authorization`
   header. On `2xx` it copies those three headers onto the request; otherwise
   corvauth's response (e.g. `401`) goes straight back to the client.
3. Strips `/api` before proxying.

`CADDY_HOST` (bind address), `GATEWAY_PORT`, `TLS_CERT_FILE`, and `TLS_KEY_FILE`
come from the environment, with current values as fallback defaults. Changing
`GATEWAY_PORT` also needs a matching update to `docker-compose.yml`'s `ports:` mapping.

## dex

**Image:** `ghcr.io/dexidp/dex:v2.46.1` (`dex`)
**Config:** `examples/dex/config.yaml` · **Docs:** https://dexidp.io/docs/

[Dex](https://github.com/dexidp/dex) as the OIDC/OAuth2 provider, configured for
E2E testing only: the `mockCallback` connector signs every login in as the same
mock user (`kilgore@kilgore.trout`, `email_verified: true`) with no login form,
and `skipApprovalScreen: true` skips consent. Tokens are RS256-signed; storage is
in memory. The issuer is `https://localhost/oauth2`, so Dex serves all endpoints
under `/oauth2/` (`/auth`, `/token`, `/userinfo`, `/keys`,
`/.well-known/openid-configuration`).

Dex listens on `dex:5556`. The gateway routes `/oauth2/*` here because
`OAUTH2_AUTH_URL=https://localhost/oauth2/auth` sends the browser here as part of
the client-facing login flow. From `/oauth2/auth`, follow the 302/303 redirects
through Dex until `Location` reaches `https://localhost/auth/callback`.

`examples/dex/config.yaml` registers the `test-client` / `test-secret` client with
redirect URI `https://localhost/auth/callback`.

## corvauth

**Image:** `ghcr.io/lucap9056/corvauth:0.4`
**Source:** https://github.com/lucap9056/corvauth

Device-bound session authentication server, running in **managed users** mode:
`DATABASE_URL` is set, `DB_AUTO_CREATE_SCHEMA=true` creates `users` and
`auth_user_devices` on startup, and `ALLOW_REGISTRATION=true` inserts first-time
users. It signs in through Dex as a generic provider
(`OAUTH2_PROVIDER=test-provider`): the browser goes to
`OAUTH2_AUTH_URL=https://localhost/oauth2/auth`, and corvauth calls
`OAUTH2_TOKEN_URL`/`OAUTH2_USERINFO_URL` directly on `http://dex:5556/oauth2/...`.

Routes (mounted at `/auth/*`, prefix stripped before reaching the service):

| Method & path | Input | Returns |
|---|---|---|
| `GET /login` | — | `{message:{url}}` |
| `GET /callback` | query `code`,`state`; optional header `X-Device-Name` | `{message:{access_token, refresh_token}}` + `refresh_token` cookie |
| `GET /verify` | Bearer | `204` + `X-Forwarded-User-Email`/`X-Forwarded-Device-ID`/`X-Forwarded-Username`, or `401` |
| `GET /verify-optional` | Bearer (optional) | `204`, identity headers only when signed in |
| `POST /refresh` | `refresh_token` cookie or body | `{message:{access_token, refresh_token}}` (rotates both) |
| `POST /refresh-access` | same | `{message:"<access_token>"}` (access only) |
| `POST /refresh-status` | same | `{message:{device_id, issued_at, expires_at}}` |
| `POST /logout` | same (optional) | `{message:"Logged out and device session revoked"}` |
| `DELETE /users/me` | Bearer | `{message:"Account deleted"}`, removes all sessions |
| `GET /health` | — | `200 OK` |

`GET /verify` is also the gateway's `forward_auth` target for `/api/*`. Full API
and configuration: [corvauth docs](https://github.com/lucap9056/corvauth/tree/main/docs).

## core

**Image:** `ghcr.io/lucap9056/magic-conch-shell/core:3.0.0` · **Source:** `core/` (this repo)

The LLM engine, served over gRPC at `GRPC_ADDRESS=:50051` for `magic-conch-api`
(`core:50051`). Contract is `core/structs/structs.proto`: unary
`AssistantService.Chat(Request) → Response`, where
`Request{language: Language, current_message, history_messages}` and
`PromptMessage{parts: []PromptPart{type, content, mime_type}}`. Errors are gRPC
status codes whose message is a user-facing reply.

Key env vars: `LLM_API_KEY` (Gemini — ⚠ `examples/.env` holds a real key in
plaintext, gitignored but treat as sensitive), `MODEL_NAME`, and
`FILE_TOKEN_KEYS=${FILE_TOKEN_KEY}` to verify the filetokens issued by
`fileupload`. On startup it lists the models available to `LLM_API_KEY` and
exits if `MODEL_NAME` is missing from that list. The compose healthcheck runs
`grpc_health_probe -addr=localhost:50051`, and `magic-conch-api` waits for it.

## fileupload

**Image:** `ghcr.io/lucap9056/magic-conch-shell/fileupload:2.0.0` · **Source:** `fileupload/` (this repo)

`POST /upload` on `:8080` (routed from `/api/upload`; the gateway validates the JWT).
Accepts `multipart/form-data` field `file`, max 20 MiB. MIME sniffed via
`http.DetectContentType`, falling back to extension-based detection; allow-list
is `image/png`, `image/jpeg`, `image/webp`, `image/heif`, `image/heic`. Uploads to
the Gemini Files API, signs `{uri, mime, exp}` into a filetoken with
`FILE_TOKEN_KEY`, and returns `{message:{key: "<filetoken>", mime_type}}`. The
token is valid for 47h, within the 48h Gemini Files retention. `REDIS_URL` caches
issued tokens per file hash so re-uploading the same image returns the same token.

`GEMINI_API_KEY` and `core`'s `LLM_API_KEY` must belong to the same Gemini
project — here both read `${LLM_API_KEY}`.

## magic-conch-api

**Image:** `ghcr.io/lucap9056/magic-conch-shell/httpserver:3.0.0` · **Source:** `httpserver/` (this repo)

Thin HTTP↔gRPC bridge to `core` — the actual chat endpoint. `GET /health`, and
`POST /` on `:8080` (routed from `POST /api/`; the gateway validates the JWT). Body is
decoded with `protojson`, max 1 MiB: `language` takes `LANGUAGE_EN`/`LANGUAGE_ZH`
(or `1`/`2`), field names accept snake_case or camelCase, unknown fields → `400`,
and `current_message` is required. Calls `core` over gRPC with a 5s timeout and
maps the status code:

| gRPC code | HTTP | `message` |
|---|---|---|
| `InvalidArgument`, `FailedPrecondition` | `400` | `core`'s user-facing reply |
| `ResourceExhausted` | `429` | `core`'s user-facing reply |
| `Unavailable` | `503` | `service temporarily unavailable` |
| `DeadlineExceeded`, `Canceled` | `504` | `request timed out` |
| anything else | `500` | `internal server error` |

## postgres

**Image:** `postgres:16-alpine` — backs `corvauth` only. corvauth creates its
tables on startup (`DB_AUTO_CREATE_SCHEMA=true`): `users` and `auth_user_devices`.

Data persists to `./postgres_data` (bind mount, gitignored) — delete it to reset
the DB.

## redis

**Image:** `redis:7-alpine` — shared, unnamespaced beyond key prefixes:

| Consumer | Key pattern | Purpose | TTL |
|---|---|---|---|
| `fileupload` | `fileupload:token:<mime>:<sha256>` | file hash → issued filetoken | token lifetime minus 5 min (~47h) |
| `corvauth` | internal (login `state`, device secret cache, `/callback`/`/refresh` dedupe) | login-flow state + session cache | state: short-lived |

Redis runs in memory: a restart clears pending logins and cached device
secrets; `postgres` keeps users and device sessions.
